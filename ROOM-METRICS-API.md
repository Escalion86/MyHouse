# Площади и объёмы помещений

В интерфейсе: список помещений → **Площади и объёмы всех помещений**. У выбранной комнаты площадь и объём также показаны в боковой панели.

Данные вычисляются из текущей геометрии `src/model/layout.js` общим модулем `src/model/roomMetrics.js`, используемым интерфейссом и сервером. Поверхности пола общие с 3D-моделью. Отдельные значения площади из старого техплана не используются. После изменения геометрии и развёртывания проекта данные пересчитываются; сохранять копии результатов в MongoDB не нужно. Сохранённые проверки замеров сами геометрию не изменяют.

## Запросы

- `GET https://house.escalion.ru/api/rooms/metrics` — все комнаты, итоги по этажам и всему дому.
- `GET https://house.escalion.ru/api/rooms/room-10/metrics` — детская; вместо `room-10` можно указать любой `id` из списка.

Требуется обычная сессия владельца проекта. Токен Home Assistant здесь не используется. В браузере после входа можно открыть URL напрямую. Ответы имеют `Cache-Control: no-store`.

Для внешнего клиента сначала выполните `POST /api/login` с заголовками `Origin: https://house.escalion.ru`, `Content-Type: application/json` и JSON `{ "username": "ВАШ_ЛОГИН", "password": "ВАШ_ПАРОЛЬ" }`. Сохраните cookie из ответа и передавайте в следующих запросах. Это учётная запись проекта из серверного `.env`, а не учётная запись HA. Cookie — секрет, не публикуйте её. При ответе `401` нужна новая сессия. Неизвестный ID комнаты возвращает `404`.

Пример после сохранения cookie в `cookies.txt`:

```sh
curl --cookie cookies.txt https://house.escalion.ru/api/rooms/metrics
curl --cookie cookies.txt https://house.escalion.ru/api/rooms/room-10/metrics
```

## Формат

Общий ответ содержит `schemaVersion: 1`, `source: "model-geometry"`, `units`, массив `rooms`, `totals`, `floors` и пояснения `method`. Ответ одной комнаты содержит те же метаданные, `method` и объект `room`.

| Поле комнаты | Значение |
| --- | --- |
| `id`, `name`, `floor` | Постоянный ID, название и этаж |
| `enclosed` | Закрытое помещение или открытый балкон |
| `areaM2` | Площадь пола внутри стен, м²; без лестничного проёма второго этажа |
| `footprintAreaM2` | Внутренний контур помещения в плане, м², включая проём |
| `stairOpeningAreaM2` | Площадь отсутствующего пола, м² |
| `ceilingHeightM` | Высота отделанного потолка, м; для балкона `null` |
| `volumeM3` | Объём помещения, м³; для балкона `null` |
| `stairwellExtraVolumeM3` | Добавка к объёму первого этажа под лестничным проёмом, м³ |

`totals` и элементы `floors` содержат `enclosedAreaM2`, `enclosedVolumeM3`, `outdoorAreaM2`. В `floors` дополнительно есть номер `floor`. Числа в API округлены до 6 знаков после запятой, в интерфейсе — до 2; это точность отображения, не точность обмеров.

## Правила расчёта

Площадь — сумма внутренних поверхностей пола. Объём — внутренний контур × высота отделанного потолка. Перегородки, наружные стены и запотолочное пространство исключены. Мебель, ступени и мелкие выступающие предметы не вычитаются. Это геометрические данные для дальнейших расчётов, не расчёт воздухообмена или мощности отопления.

Лестница: нижняя часть воздушного пространства относится к первому этажу до отметки пола второго этажа, верхняя — ко второму. Таким образом, над проёмом второго этажа нет площади пола, но есть объём воздуха. Дополнительный объём первого этажа равен площади пересечения комнаты с проёмом × разности отметки второго этажа и высоты её потолка.

Открытый балкон (`room-6`, в исходной модели «Мансарда») учитывается отдельно по площади, без объёма закрытого помещения. Гараж и баня не включены: их внутренние размеры ещё не моделировались.

Высоты первого этажа: 2,88 м в комнатах с натяжным потолком, 3,00 м в ванной, 2,60 м в котельной. На втором этаже используется текущая высота модели 2,70 м, пока не подтверждённая обмером. Другие непроверенные размеры модели также влияют на результат.

Новых переменных `.env` для этих запросов нет.
